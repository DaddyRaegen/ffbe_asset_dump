# Build 207 publication

Build 207 changes the download-screen comma spacing and the APK version only. It uses the exact published 206 event catalog, side manifest, GitHub packs, menus and banners. This directory contains no asset-release uploader. Do not change the frozen 206 inputs or any published 206 file.

Required inputs are `staged_build/DOWNLOAD_SPACING_APK_BUILD.json`, `staged_build/SIGNED_SPACING_QUALIFICATION.json` and `audit/DOWNLOAD_SPACING_PLAN.json`. The signed report must bind the exact APK SHA/size, version 207, published 206 baseline, exact two changed application members, unchanged catalog/side-manifest hashes, and the sealed spacing plan. The plan contains exact finite script replacement operations, separately from the single PATCH_VERSION increment. The local publication verifier independently compares ZIP member bytes and the expected script. The three existing v1 signing metadata files are regenerated by signing and recorded separately; no other member may change.

Prepare locally with `node publication/prepare_site.mjs`, then review locally with `node --experimental-vm-modules publication/review_publication_local.mjs`. Neither command makes network calls. All eight previous beta APK links, the 206 asset references, and phone-test-pending labels must remain.

After qualification and scope review, the root publisher may run `node publication/publish_site.mjs --stage` and then `node publication/publish_site.mjs --activate`. Stage uploads only the immutable 207 APK. Activation uploads the three immutable release metadata files, changes only `channels/beta/patch_version.json` on the beta branch, verifies its public readback, and updates only `downloads/beta/index.html`. The updater uses version/versionCode 207, asset_version 206, both APK URL fields and an empty changelog array.

Both modes check production main/latest, the six protected public files, unchanged 206 event metadata and the stable 203 asset manifest pointer. No release creation, asset pack upload, production updater write, manifest write, code push or native/runtime change is permitted by these tools. Runtime, phone appearance and saves remain pending until Kev tests the exact APK.

Retained source copies are archival. Rebuilds require a fresh workspace, a new output version and explicit configuration; do not run archival sources in place against already published 207 defaults.
